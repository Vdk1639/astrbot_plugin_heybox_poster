# 小黑盒冲浪板

在一个 AstrBot 插件内管理小黑盒账号、发帖、评论、通知轮询和主动浏览，使用统一管理面板审核内容。

**当前开发版本：v0.8.0（dev）** · AstrBot 要求 **>=4.26.0,<5**。管理页依赖 `astrbot.api.web` 和已登录的 Dashboard 会话。

> 使用前请阅读下方的“使用约定与免责声明”，遵守小黑盒现行条款、社区规范及账号使用规则。

📌 **快速上手：** 安装插件 → 在面板扫码登录 → 配置审核与浏览来源 → 按需启用 `heybox_community` 机器人。

## ✨ 功能概览

- 多账号档案扫码登录、登录检查和安全退出；发帖与评论共用同一套凭据。
- 发布动态、长文和草稿，选择话题与可见范围；向帖子或指定楼层发表评论。
- 原生平台 **`heybox_community`**，机器人页面显示为 **小黑盒冲浪板**，接入 AstrBot 会话、人格和 Agent 回复流程。
- 轮询 @ 提及及评论回复，按配置主动浏览分区或推荐流；统一发帖审核与评论审核。
- 管理面板包含状态、设置、浏览来源、事件、运行日志、SSE、诊断和存储清理；主动浏览候选位于“主动评论候选”。
- 发布权限、冷却、持久审核队列、发送去重及未知结果保护。

这是整合后的单插件版本：发帖、评论、通知回复和主动浏览共用账号档案、状态面板与审核队列。

## 🚀 安装与首次使用

### 环境要求

- AstrBot **>=4.26.0,<5**。
- 管理面板需要 `astrbot.api.web` 及已登录的 Dashboard 会话。

### 安装与登录

1. 将本插件目录 `astrbot_plugin_heybox_poster` 放入 AstrBot 的 `data/plugins/`，安装 `requirements.txt` 后重载插件。
2. 打开 **AstrBot WebUI → 插件 → 小黑盒冲浪板 → 可视化视图**，进入管理面板。
3. 在“设置”的账号档案中添加账号，为每个档案指定不同的 `profile_id`，保存后在“扫码登录”选择对应档案扫码。默认档案为 `default`。
4. 在“发布编辑”选择发布账号，填写帖子或评论；按当前模拟运行与审核设置提交，在对应审核页处理。
5. 需要通知轮询或主动浏览时，在 **AstrBot 机器人页面**新增 **小黑盒冲浪板**，类型为 `heybox_community`，将机器人的 `profile_id` 设置为已登录档案的同名值并启用。为需要运行这些任务的每个档案配置相应机器人。

**只需安装本插件，不需要第二个“小黑盒适配器”插件。** 仅通过面板或指令手动发布时，不要求创建轮询机器人。旧适配器使用的类型与 `heybox_community` 不同，旧机器人不会自动变成新机器人；启用整合插件前停用同一小黑盒账号的旧轮询实例，避免两套插件或两个档案同时轮询、重复回复同一账号。

### 账号档案与机器人

`profile_id` 是本地档案标识，不是小黑盒 UID，可使用字母、数字、下划线和短横线。默认发帖账号由 `publishing.profile_id` 决定；面板可单独选择其他档案，发帖及评论 LLM 工具也接受 `profile_id`。原生通知回复使用收到事件的机器人档案，不会改用默认发布账号。

## 🛡️ 模拟运行与审核

### 默认开关

首次配置时，`publishing.dry_run`、每个档案的 `dry_run`、`publishing.post_review_required`、`publishing.comment_review_required` 均默认开启；`proactive_feed.enabled` 默认关闭，主动浏览的 `dry_run` 和 `review_required` 默认开启。

| 操作 | 实际发送前需关闭的模拟开关 | 默认审核入口 |
|---|---|---|
| 手动发帖、草稿、手动评论、通知评论 | `publishing.dry_run` 和所用 `profiles` 档案的 `dry_run` | 发帖审核 / 评论审核 |
| 主动浏览生成的评论 | 上述两项及 `proactive_feed.dry_run` | 评论审核 |
| `/xhh删除` | `publishing.dry_run` 和默认发布档案的 `dry_run` | 不进入发布审核队列，指令按权限直接执行 |

任何适用的模拟开关仍开启，都不会真实发送。关闭模拟运行不会自动批准已有待审内容；只有需要直接发送新内容时，才关闭对应的发布审核开关。主动评论还受 `proactive_feed.review_required` 约束，生成过程本身也可能要求审核。

### 审核状态与账号绑定

- **已登录且开启审核：** 提交先返回 `pending`，即使正在模拟运行，也会进入审核队列。
- **模拟批准：** 返回 `dry_run`，未实际发送，审核项仍可能保持 `pending`。以刷新后的审核状态为准。
- **未登录且模拟运行：** 可返回预演结果而不生成审核项；真实发布前仍需扫码登录。
- **发送结果未知：** `send_unknown` 必须先在小黑盒核实，不能重新批准、拒绝或自动重发。后台中断时未完成的审核发送会保守转为未知状态。

审核项绑定提交时的档案和账号 UID。档案后来换成另一个账号时，不能用新账号发送旧账号的审核内容。

发帖与评论审核页各显示最近 100 条记录，包含全部状态。已发送、已拒绝、发送失败及其他非待审记录只读；明确失败会显示错误原因，发送结果未知则保留人工核对提示。

本地额度或风险策略阻止批准时，显示“未发送，仍待审核”和原因，审核项保持 `pending`，可在额度重置或处理策略后重新审批，也可拒绝。即使随后刷新列表失败，已确认仍待审的卡片也恢复按钮。普通 `pending` 表示已加入队列；网络丢失响应、`sending` 和 `send_unknown` 仍须核对，不能直接重发。

### 主动评论候选

“主动评论候选”处理主动浏览生成的候选。在该页面确认后，候选按当前档案 UID 绑定并转入统一评论审核，返回 `queued`，**不会直接发送**。还需在“评论审核”核对账号与内容，再次批准；模拟运行与审核规则仍生效。

## 💬 指令与 LLM 工具

### 指令

原有指令格式保持兼容，使用 `publishing.profile_id` 指定的默认发布档案：

```text
/xhh登录
/xhh状态
/xhh话题 Steam
/xhh发帖 标题|正文|话题名或ID
/xhh我的帖子
/xhh删除 帖子ID
/xhh评论 帖子ID|评论正文
/xhh评论 帖子ID|回复正文|父评论ID
```

`/xhh发帖` 发布动态；配置 `publishing.default_topic_ids` 后第三段可省略。`/xhh评论` 第三段可省略，省略时评论主帖。需要逐次指定账号、长文、草稿或根评论 ID 时，使用面板或 LLM 工具。

### LLM 工具

| 工具 | 用途 |
|---|---|
| `xhh_account_status` | 检查默认发布账号登录态 |
| `xhh_search_topics` | 搜索社区 / 话题，最多返回 5 条 |
| `xhh_publish_post` | 动态、长文或草稿；可选 `profile_id`、`topic_ids`、`mode`、`draft` |
| `xhh_my_posts` | 查询默认发布账号最近的帖子 |
| `xhh_publish_comment` | 提交评论；参数含 `post_id`、`text`、可选 `parent_comment_id`、`root_comment_id`、`profile_id` |

例如：“用 `profile_id=work` 的账号，向帖子 `123456` 评论‘感谢分享’，提交审核。”确保模型已启用对应工具。发帖指令与工具优先使用明确话题 ID；名称搜索会选取首个匹配，可先搜索确认。面板话题输入按数字 ID 处理。

## ⚙️ 配置与浏览来源

### 发布配置

统一面板的“设置”和 AstrBot 插件配置共用配置对象。现行发布配置位于 **`publishing` 分组**。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `publishing.profile_id` | `default` | 未显式选择账号时使用的发布档案 |
| `publishing.dry_run` | `true` | 全局发布与删除模拟开关 |
| `publishing.post_review_required` | `true` | 帖子先提交审核 |
| `publishing.comment_review_required` | `true` | 手动评论和原生评论先提交审核 |
| `publishing.default_topic_ids` | 空字符串 | 默认话题 ID，多个用英文逗号分隔 |
| `publishing.view_limit` | `2` | `1` 公开 / `2` 粉丝可见 / `3` 仅自己可见 |
| `publishing.allowed_users` | `[]` | 手动指令与工具的写权限；留空仅管理员 |
| `publishing.cooldown_seconds` | `60` | 账号实际发送间隔；手动发帖另有发送者冷却 |
| `publishing.rate_limit_cooldown_seconds` | `600` | 命中限流后的持久冷却秒数 |
| `publishing.request_timeout` | `20` | 发帖请求超时秒数 |
| `publishing.outbox_path` | 空字符串 | 发帖 outbox 路径；留空使用插件数据目录 |
| `publishing.outbox_dedup_seconds` | `600` | 成功发送去重窗口；待处理或未知结果持续阻止重复提交 |
| `publishing.outbox_purge_days` | `7` | 启动时清理过期失败 outbox 记录；`0` 不清理 |
| `publishing.comment_daily_limit` | `30` | 同一发送账号所有来源的真实评论日上限；`0` 不限，整数 0–100000 |

### 通知处理与评论额度（dev）

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `reply.reply_thread_once` | `true` | 同一发送账号、同帖、同根楼层只接受一次自动通知回复任务；待审与发送未知持续占位，会限制正常追问 |
| `reply.reply_daily_per_user` | `5` | 每个发送账号对每个已验证 UID 的每日通知处理次数；`0` 不限 |
| `reply.reply_daily_total` | `30` | 每个发送账号每日接受的通知处理总次数；`0` 不限 |
| `reply.reply_owner_exempt` | `true` | 已验证且匹配非空主人 UID 时，仅豁免单用户处理上限 |

数量配置严格接受整数 0–100000；布尔开关只接受布尔值，显式 `null`、字符串、浮点数及把布尔值当整数均被拒绝。旧配置缺少新字段时补默认值，设置页复用 schema 表单。`0` 只关闭对应数量上限，楼层去重仍由独立开关控制。

概览为每个档案显示“今日通知处理”和“今日真实评论”两套次数/额度。同一个发送 UID 的多个档案共用账号预算及楼层占位，不同 UID 独立；每日按 UTC 日期计数，北京时间 **08:00** 重置。缺 UID 的通知共用该发送账号的一个用户预算桶，这不表示它们是同一个人，也不授予主人权限。主人仍受楼层、账号总处理预算、真实评论上限、硬名单、审核和冷却约束。

通知处理次数在接受任务、准备读取上下文时消耗，上下文读取或生成失败、空回复、模拟运行、审核拒绝均不退还；真正重新生成的尝试继续计次。这是保守的处理预算，不是精确模型调用数或 Token 配额，不能用“今日回复”或“今日主动 AI 请求”替代。

真实评论额度由通知、主动浏览、面板、指令/工具及会话评论共享。待审、生成和模拟不占发送额度；`sending/sent/send_unknown` 占用，确定未发送的失败释放。跨日审批按实际发送尝试当天计数，未知发送确认成功不重复计数。无根楼层时沿用解析器的评论 ID 或帖子级作用域，不猜测平台未提供的楼层关系；已发送楼层去重受 `retention.dedup_days` 保留期限制，未知占位不自动释放。

这些默认数值是插件策略，不是平台官方安全阈值；本地数据库无法限制同账号在另一个独立部署的行为。

### 事件聚合与人工风险管理（dev）

事件页默认保留按事件查看，支持档案、UID、状态、帖子、关键词、时间与分页。首次切换“按用户”且未设置时间时，页面显式填入最近 **7 天**，显示范围并允许修改或清空；API 未传时间仍查询全部保留记录。时间输入使用浏览器本地时间，列表显示北京时间。

聚合按档案和 UID 隔离，事件数、帖子数和状态/类型分布只统计当前筛选结果，风险分则显示当前快照。主动 AI 回复表示主动浏览来源，不表示帖子作者主动触发通知。下钻携带档案、UID 及当前筛选，返回时保留筛选和页码。缺 UID 每条独立显示“UID 未提供”，用 `event_id` 下钻，不合并身份、不凭昵称封禁或调分。尚未接入风险数据时显示“未启用/未接入”，不假报 0 分。

| `risk` 配置项 | 默认值 | 范围/说明 |
|---|---|---|
| `enabled` | `true` | 评估新事件；关闭不解除人工封禁，不补评历史积压 |
| `auto_filter_enabled` | `false` | 默认只观察，观察误判后由管理员显式开启自动过滤 |
| `watch_score` | `20` | 整数 1–999，观察起点 |
| `auto_filter_score` | `60` | 整数 2–1000，必须大于 `watch_score` |
| `flood_window_minutes` | `10` | 整数 1–1440，行为窗口及规则去重窗口，单位分钟 |
| `flood_threshold` | `8` | 整数 2–1000，包含当前通知 |
| `burst_score` | `20` | 短时高频加分，整数 0–1000，`0` 关闭本规则 |
| `repeat_score` | `15` | 连续重复内容加分，整数 0–1000，`0` 关闭本规则 |
| `injection_score` | `25` | 明确指令覆盖/权限伪装加分，整数 0–1000，`0` 关闭本规则 |
| `privacy_score` | `30` | 明确索取非公开信息加分，整数 0–1000，`0` 关闭本规则 |
| `owner_exempt` | `true` | 可信主人免自动评分和自动过滤；人工封禁及硬名单仍有效 |

分数为 0–1000 的启发式信号，不能证明用户恶意。正常技术讨论中出现 token、配置或日志等词不直接认定攻击；不增加模型风险裁判或网络调用。历史回填、时间不明的通知不计短时行为风险，不自动补评历史事件。

“用户风险记录”支持档案、UID、等级和人工封禁筛选，详情分页展示快照与审计，包括规则/人工操作、实际分数变化、时间、操作者和脱敏详情。等级达到 `blocked` 只表示已达阈值；自动过滤未生效时明确显示该状态。

**人工封禁独立于评分总开关和自动过滤开关，关闭评分不会解封。** 人工封禁、解除与调分均需确认档案、UID、备注及是否清分。解除默认保留分数；若自动过滤仍生效，详情继续提示风险阈值阻止处理。勾选清分只归零分数，保留审计与已有硬黑名单。历史档案只读；解除不会自动重放已忽略的通知，也不能撤销已经开始或未知的发送。调分不是幂等操作，面板禁用重复提交且不自动重试；结果未确认时先刷新并核对审计。

### 权限与筛选

白名单可写为 `["qq:123", "xhh:456"]`；裸 ID 会匹配不同平台的同名 ID。显式配置白名单后按名单放行；账号管理页独立使用 Dashboard 鉴权，白名单不会授予面板权限。原生通知和主动浏览的用户、作者、关键词筛选位于 `permissions` 等分组。

### 浏览来源与其他设置

在“浏览来源”选择真实分区，或配置推荐流回退分类。探测使用扫码页当前选择的档案；浏览来源配置由 `proactive_feed` 管理。真实分区优先；未选分区或所选分区本轮全部请求失败时使用回退分类。设置页还能配置轮询间隔、回复、模型、网络、日志和保留期限。

## 🔐 凭据与接口权限

### 凭据保存与退出

插件使用统一账号档案保存凭据。升级整合版后请在管理面板为需要使用的档案重新扫码登录；旧版顶层配置和凭据不会自动导入。

新登录凭据按档案保存在插件数据目录的 `credentials/<profile_id>.json`。覆盖登录前保留对应 `.json.bak`，失败时回滚。安全退出需确认，清除所选档案当前凭据及其 `.json.bak`。凭据与备份含敏感信息，不要提交、分享或粘贴到诊断输出中。

### 管理接口鉴权

面板只通过已认证的 AstrBot bridge 调用插件 Web API，路由前缀为 `/astrbot_plugin_heybox_poster/`。账号、设置、发布、审核、事件、日志 SSE、存储和诊断接口均要求 Dashboard 登录；批准审核、退出登录和执行存储清理还要求 `confirm: true`。这些接口不是匿名 webhook，也不提供绕过 Dashboard 的 webhook 密钥入口。`config` 与 `config/schema` 仅暴露现行配置分组。

事件聚合复用 `GET events?group_by=uid`，平铺/下钻可传 `profile_id`、`uid` 或匿名 `event_id`。风险列表为 `GET risk/users`（`profile_id/uid/level/manual_blocked/page/page_size`），详情为 `GET risk/users/detail`（`profile_id/uid/page/page_size`），返回 `{user: 当前快照, events: 分页审计}`。人工操作为 `POST risk/users/block|unblock|adjust`，body 使用 `profile_id`、`uid`、最多 200 字的 `note`、JSON 布尔值 `confirm: true`；解除可加 `reset_score` 布尔值，调分须加整数 `delta`（-1000..1000）。操作者来自已认证会话，客户端不自报身份。读取可看历史档案，写入仅限当前配置档案。调分接口不应自动网络重试。
